# UI foundation

The project generates Unity scenes on first interactive editor open. Open with Unity 6000.6.6f1 and allow Foundation 1 and Course 1 generation to finish. MainMenu is registered first, and the generator opens it after creation. If scenes already exist from an older version, back up any edited MainMenu scene and use **Bikini Wipeout > UI > Rebuild Main Menu Scene**; this replaces that scene, not the course or player. Existing course scenes retain their old HUD/results until explicitly regenerated using their existing rebuild commands; those commands overwrite generated course content, so back up custom edits first.

Course 1 is configured as `Course_SplashdownGauntlet`. The menu checks both the readiness flag and whether Unity can load the scene from build settings. Course 2 is explicitly disabled and has no scene reference. Course entries are serialized on MainMenuController; the current generated layout exposes two cards and needs UI extension to expose additional entries.

The available player is the player prefab selected by the existing Course 1 builder. No other character was verified or integrated; the selection screen persists the existing-player ID and does not swap prefabs. Audio uses the existing AudioManager, AudioLibrary and volume controls. Graphics settings use PlayerPrefs and Unity's quality and resolution APIs. Existing pause controls include volume sliders. The menu uses the existing input-system UI module and back accepts Escape or gamepad east button.

Validation in Unity: generate scenes, run **Bikini Wipeout > Validate Project**, then run EditMode and PlayMode tests. Start from MainMenu, exercise course selection and unavailable Course 2, confirm the player, finish the course, use retry/course select/menu, pause and resume with keyboard and controller, and verify volume and graphics settings persist after restarting. Inspect appearance, scene references, audio and player controls in a Windows build. None of these are substitutes for an actual playtest.
